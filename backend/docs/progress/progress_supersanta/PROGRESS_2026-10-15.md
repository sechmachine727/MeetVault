### Video coverage added after the owner asked

The first pass seeded **audio only**, so the whole video path was untested. Now the seed uploads a
real H.264 MP4 (`ffmpeg testsrc`) per meeting as `kind=video&start_offset_ms=2000`, and the specs
assert two recording rows with their kinds, the rendered `starts at 0:02` offset, the shared player
swapping to a `<video>` element with a real duration, and a video download. That immediately
exposed two more defects: the player was hardcoded `<audio>` (a screen recording could not be
watched at all) and the caption never followed a track switch; and a conditional child passed to the
raw DOM `append()` rendered the literal text `nullnull` on every detail header (fixed with
`appendAll()` + a stray-null text-node net that was proven to bite). `screens/04b-screen-video.png`
shows the video frame rendering.

### Defects found by the tests and fixed (each with a regression test)

1. CSP blocked the `blob:` media source — Chromium refused every recording and all seeks no-op'd;
   `media-src 'self' blob:` + a header assertion.
2. `create_app()` read the lru-cached settings at import time, so the first test of a session ran
   against the dev `_local.db` (`UNIQUE constraint failed: users.email` in `tests/e2e`); a fresh
   `Settings()` plus a subprocess cache-size test that was proven to bite.
3. A 401 from `POST /v1/auth/login` fired the session-expired path, wiping the "wrong password"
   message; the hook now skips the login path.
4. Naive server timestamps were parsed as local time (elapsed read `7h 5m` for a 92 s-old job);
   `parseServerTime` pins a missing offset to UTC.
5. Staleness cried stale over current data on three surfaces (list banner, row pill, analysis
   banner — the bundle copies status' unfiltered list); all three now apply stale-minus-fresh.
6. Mock badges said the wrong thing (aggregate `/status.mock` on a list row); now "Mock transcript"
   (detail, from `meeting.is_mock`) and "Mock analysis" (analysis tab, from `run.is_mock`).
7. `DELETE /v1/transcripts/{id}` cascades the analysis away with no warning (measured on a fresh
   seed: documents and runs emptied, `/analysis` summary gone); the console now confirms with the
   cascade stated. Backend follow-up recorded.
8. Activating a different transcript version leaves a stale analysis looking current (probe:
   `fresh_kinds` and every `stale=False` unchanged after activation). Backend follow-up recorded.
9. Search only reacted on blur (`change`); now `input`, debounced.
10. Deleting the recording that was playing revoked its blob before the "is this loaded" check.

### Email sign-up (added this session, after the owner asked)

`POST /v1/auth/register` creates an account from an email + password and returns the same
`LoginOut` as login, so signing up signs you in; the console gained a `#/signup` route, a
`views/signup.js` screen and links between the two screens. All the account rules now live in one
module (`src/mvb/accounts.py`) used by BOTH the endpoint and `python -m mvb.admin create-user`, so
the two provisioning paths cannot drift. Gated by `MVB_ALLOW_SIGNUP` (default on).
