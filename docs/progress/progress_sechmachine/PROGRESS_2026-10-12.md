# PROGRESS_2026-10-12

Owner: sechmachine

## Objective

Turn the pull request reviewer into a gate that posts a real review with a verdict instead of a
plain comment, returns the pull request to draft on every push and on a Change Needed verdict, and
re-opens it only when the owner re-confirms the checklist in the description and every review
thread is resolved. Move the reviewer to `9router/ocg-muse-spark-1.3-contributor` with the
local model catalog injected for its large context window.

Done when the workflows exist, the pure decision logic is covered by a runnable check, and every
piece that still needs a live pull request is named rather than asserted.

## Open threads

- The loop itself is unverified: the draft-on-push, the re-open gate, the dispatch chain, and the
  inline-comment anchoring all need a merged workflow and a real pull request with a runner.
- `openai/codex-action@v1` is deliberately unpinned; the rubric records that as accepted.
- Whether the router accepts `--output-schema` through the Responses proxy is untested. If
  it does not, the review prompt still demands JSON and the module tolerates surrounding prose, so
  the fallback is a comment-style review rather than a failure.
- The reviewer cannot build or exercise the WinUI app on the Linux runner, so a change to
  `src/MeetVault` is judged from code and an unverified summary line. Moving the review job to
  `windows-latest` would allow a real build at the cost of the action's `unsafe`-only safety
  strategy there; the owner has not chosen.
