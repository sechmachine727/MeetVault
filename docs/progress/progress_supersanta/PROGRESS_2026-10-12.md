Date: 2026-10-12 · contributor: supersanta (implemented by Clanker Master + 1 Clanker Slave)

## Current picture

`D:/workspace/Meetvault_Backend` is a standalone FastAPI + SQLAlchemy + Alembic service that
gives MeetVault post-meeting re-processing: upload a finished recording, run
`media_probe → transcribe → diarize → align → analyze` asynchronously, then read an improved
transcript, speaker labels, agenda/sections/summary/decisions/action items and section-scoped
Q&A. AI engines are pluggable (mock by default, LM Studio / OpenCode / faster-whisper /
pyannote), and a missing engine degrades to a labelled mock instead of blocking startup.

The MeetVault client is **untouched**: no file in `D:/workspace/MeetVault` was modified except
the untracked plan document.

## Decisions worth keeping

- **One job at a time in the chain.** `enqueue_pipeline` creates exactly one job; the worker
  creates the next step after a success. Pre-creating the whole chain *and* chaining in the
  worker ran steps 2–5 twice — caught by the e2e job-order assertion, not by unit tests.
- **Alignment is mandatory, not cosmetic.** MeetVault's exported transcript has no timings, so
  every imported segment is placed on the probed media timeline; otherwise playback drifts.
- **Staleness over silent overwrite.** A new transcript/media marks older analysis `stale`;
  the API always serves the newest fresh document and reports `stale_kinds`.
- **Mocks are labelled at three layers** (provider result → DB row → API response) plus
  `[mock]` text prefixes, so synthetic output cannot be mistaken for a real result.
- **`psycopg` lives in the `prod` extra** so the core install works on this box's Python 3.14.

## Remaining / not verified here

- **Docker image, compose stack and Postgres** — no Docker daemon on this box. Written and
  YAML-validated; the CI `docker` and `postgres` jobs are the verification path.
- **Real AI engines** — interfaces and HTTP clients tested with `respx`; a live call needs
  `MVB_RUN_LIVE=1` plus the engine. OpenCode's route shape is pinned in one function.
- **Job list ordering on SQLite** is deterministic but not chronological within a second
  (second-resolution timestamps); correct on Postgres.
- **Client-side integration** is documented (`docs/INTEGRATION.md`) but no MeetVault code was
  written — by design, awaiting the user's go-ahead for client changes.
